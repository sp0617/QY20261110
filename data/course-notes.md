# 《人工智能导论》课程笔记

> 本资料是 AI 答疑助手的课程知识库，内容覆盖课程核心概念与常见疑问。助手的回答只基于这里的内容，遇到资料没有覆盖的问题会明确说明。

## 一、人工智能与机器学习基础

人工智能（Artificial Intelligence，简称 AI）是研究如何让机器表现出智能行为的技术领域，常见目标包括感知、理解、推理、决策与生成。

机器学习是人工智能的一个分支：它让程序从数据中自动学习规律，而不是由人逐条编写规则。按照学习方式，机器学习通常分为三类：

- 监督学习：使用带标签的数据训练模型，典型任务是分类与回归，例如垃圾邮件识别、房价预测。
- 无监督学习：数据没有标签，模型自行发现结构，典型任务是聚类与降维，例如用户分群、主成分分析。
- 强化学习：智能体通过与环境交互获得奖励，学习使长期收益最大的策略，例如游戏智能体、机器人控制。

数据集通常划分为训练集、验证集和测试集。训练集用于学习参数；验证集用于调整超参数和选择模型；测试集只在最后使用，用于评估模型的泛化能力。如果用测试集反复调参，评估结果会偏乐观，这属于数据泄漏的一种形式。

泛化能力指模型在未见过的数据上的表现。模型在训练集上表现很好、在新数据上表现很差，通常意味着过拟合；两者都差，通常意味着欠拟合或模型能力不足。

## 二、过拟合、欠拟合与正则化

过拟合是指模型过度记住了训练数据中的细节和噪声，导致训练集表现很好，但在验证集和测试集上表现明显下降。常见表现为训练误差持续降低，而验证误差先下降后上升。

欠拟合是指模型连训练数据的基本规律都没有学好，训练误差和验证误差都较高。常见原因是模型过于简单、特征不足或训练不充分。

缓解过拟合的常用方法：

- 增加训练数据，或使用数据增强扩充样本。
- 降低模型复杂度，例如减少网络层数或参数量。
- 使用 L2 正则化（权重衰减）抑制过大的参数；L1 正则化还能产生稀疏权重。
- 使用 Dropout，在训练时随机丢弃部分神经元，减少对特定连接的依赖。
- 使用早停（Early Stopping），当验证集指标不再提升时停止训练。
- 使用交叉验证，更稳定地估计模型性能。
- 对树模型限制最大深度、最小叶节点样本数，并进行剪枝。

偏差与方差：偏差高通常对应欠拟合，方差高通常对应过拟合。实际建模需要在两者之间权衡，使验证集误差最小。正则化强度是重要的超参数，过强会导致欠拟合，过弱则无法抑制过拟合。

## 三、神经网络与反向传播

人工神经元先对输入做加权求和并加上偏置，再通过激活函数输出。常见激活函数包括 Sigmoid、Tanh 和 ReLU。ReLU 计算简单，在正区间梯度稳定，是深层网络的常用选择；Sigmoid 的输出在 0 到 1 之间，常用于二分类的输出层。

损失函数衡量预测值与真实值的差距，例如回归常用均方误差，分类常用交叉熵。训练过程通过梯度下降不断调整参数，使损失减小。学习率决定每次参数更新的步长：学习率过大容易震荡甚至发散，过小则收敛缓慢。实践中常用 Adam 等自适应优化器，并配合学习率衰减策略。

反向传播利用链式法则，从输出层向输入层逐层计算梯度。梯度消失指深层网络中梯度逐层相乘后变得非常小，导致浅层参数几乎不更新；梯度爆炸则相反，梯度数值迅速增大。常见缓解方法包括：

- 使用 ReLU 等缓解梯度消失的激活函数。
- 使用残差连接（ResNet），让梯度可以直接跨层回传。
- 使用批归一化（Batch Normalization）或层归一化稳定训练。
- 合理初始化参数，例如 Xavier 或 He 初始化。
- 使用梯度裁剪防止梯度爆炸。

## 四、Transformer 与大语言模型

Transformer 是当前大语言模型的基础架构，核心是自注意力机制（Self-Attention）。自注意力把每个词映射为查询（Query）、键（Key）和值（Value）三个向量，用查询与所有键的相似度计算权重，再加权汇总值向量，从而让每个位置直接关注序列中的其他位置。

多头注意力（Multi-Head Attention）并行执行多组注意力，让模型同时捕捉不同类型的依赖关系，例如语法关系、指代关系和语义关系。由于自注意力本身不包含顺序信息，Transformer 需要位置编码或旋转位置编码来表示词序。

大语言模型通常采用“预训练 + 微调”的两阶段方式。预训练阶段在海量文本上学习语言规律，目标常见为预测下一个词（自回归）；微调阶段用特定任务数据让模型适应下游需求，例如指令微调与人类反馈强化学习。提示工程则是在不修改参数的前提下，通过设计输入来引导模型输出。

生成时模型按 token 逐个预测下一个 token。token 是文本切分后的基本单位，可能是一个词、一个子词或一个汉字。上下文窗口决定模型一次能处理的 token 数量，超出部分会被截断，因此长文档问答需要先切分再检索。

温度（temperature）控制输出的随机性：温度较低时输出更稳定、更保守；温度较高时输出更多样，但也更容易偏离事实。top_p 是另一种采样控制参数，通常只调整其中一个。

## 五、检索增强生成（RAG）

检索增强生成（Retrieval-Augmented Generation，简称 RAG）先把外部知识检索出来，再把检索结果放进提示词，让大模型基于资料作答。它适合课程问答、企业知识库等场景，能缓解大模型知识过时、缺乏私有数据和产生幻觉的问题。

典型 RAG 流程：

1. 文档处理：清洗资料，按标题或固定长度切分为片段（chunk）。
2. 建立索引：为片段生成向量并存入向量数据库，或建立关键词索引。
3. 检索：根据用户问题召回相关片段，常用关键词检索（如 BM25）或向量相似度检索。
4. 重排与过滤：对召回结果重新排序，去掉不相关或重复的内容。
5. 构建提示：把问题和少量高质量片段一起放入提示词。
6. 生成回答：大模型基于资料作答，并尽量标注引用来源。
7. 记录与评估：保存问答记录，收集反馈，持续优化切分与检索策略。

关键词检索与向量检索各有特点：BM25 依赖词项匹配，对专有名词和精确术语效果好，无需模型即可运行；向量检索基于语义相似度，能处理同义表达，但需要嵌入模型。实际系统常把两者结合，做混合检索。

RAG 的常见问题包括：切分粒度过大导致噪声多、过小导致语义不完整；召回不足导致资料缺失；上下文过长导致关键信息被稀释；资料本身质量差或互相矛盾。优化方向包括调整切分策略、增加查询改写、加入重排模型、控制上下文长度，以及在回答中强制引用来源。

本答疑助手采用轻量关键词检索：把 Markdown 资料按二级标题切分，对中文使用二元词组、对英文使用单词建立索引，再用 BM25 风格公式排序，取最相关的若干片段交给大模型。

## 六、提示工程

提示工程（Prompt Engineering）是通过设计输入指令来提升模型输出质量的方法。常用技巧包括：

- 明确任务与目标，避免含糊描述。
- 指定角色和回答风格，例如“你是一名课程助教，用中文分点回答”。
- 给出输出格式要求，例如 JSON、表格或固定小标题。
- 提供少量高质量示例（Few-shot），帮助模型理解期望格式。
- 要求模型先列要点再下结论（思维链），适合推理类任务。
- 明确资料边界，要求“资料中没有的内容不要编造，并说明依据”。

系统提示（system prompt）用于设定全局规则，用户提示（user prompt）承载具体任务。两者冲突时，通常应让系统提示的安全与格式要求优先。

提示注入是指用户输入中包含试图覆盖系统指令的内容，例如“忽略之前的要求”。防护思路包括：把外部资料视为数据而非指令、隔离用户输入、限制工具权限、对输出做校验，以及不把敏感信息放进提示词。

提示工程与微调的区别：提示工程不改变模型参数，成本低、迭代快，适合快速验证；微调需要训练数据和算力，能改变模型行为与风格，适合稳定的大规模任务。一般应先尝试提示工程与 RAG，再考虑微调。

## 七、模型评估与常见风险

分类任务常用指标：

- 准确率（Accuracy）：预测正确的样本占比，类别不均衡时容易失真。
- 精确率（Precision）：预测为正的样本中真正为正的比例，关注“误报”。
- 召回率（Recall）：真正为正的样本中被找出的比例，关注“漏报”。
- F1 值：精确率与召回率的调和平均，用于综合衡量。

混淆矩阵展示真正例、假正例、真负例、假负例的数量，是计算上述指标的基础。回归任务常用均方误差（MSE）、平均绝对误差（MAE）和决定系数 R²。

大模型的评估更复杂，常见方式包括：人工评估回答质量、使用公开基准测试、构造课程领域的测试集、线上 A/B 测试，以及统计引用命中率与用户采纳率。

大模型的主要风险包括：

- 幻觉：生成看似合理但实际错误的内容，可通过 RAG、引用来源和人工复核缓解。
- 偏见：训练数据中的偏见会被模型放大，需要数据审查与输出过滤。
- 隐私与安全：不应把个人敏感信息发送给外部模型，必要时做脱敏。
- 版权与合规：生成内容的使用需遵守相关资料与模型的许可协议。

## 八、常见概念辨析与课程实验

参数与超参数：参数由训练过程学习得到，例如神经网络权重；超参数由人设定，例如学习率、批大小、网络层数和正则化系数。

判别式模型与生成式模型：判别式模型学习条件概率或决策边界，直接用于分类，例如逻辑回归、支持向量机；生成式模型学习数据分布，可以生成新样本，例如朴素贝叶斯、生成对抗网络和大语言模型。

监督学习与自监督学习：监督学习依赖人工标签；自监督学习从数据本身构造训练目标，例如语言模型用前文预测下一个词，因此可以利用大规模无标注文本。

课程实验“AI 答疑助手”的完整链路：

1. 读取 data/course-notes.md，按标题切分课程资料。
2. 对问题和资料分词，计算相关度，召回最相关的片段。
3. 把片段和问题拼接为提示词，调用兼容 OpenAI 协议的 /chat/completions 接口。
4. 设置请求超时，处理网络错误、接口错误与空回答。
5. 把问题、回答、引用资料、运行模式与耗时追加写入 data/qa-records.jsonl。
6. 前端展示回答、引用来源与最近问答记录。

大模型配置通过环境变量读取：LLM_API_KEY 为密钥，LLM_BASE_URL 为兼容 OpenAI 协议的接口根地址（通常以 /v1 结尾），LLM_MODEL 为模型名称。没有配置 LLM_API_KEY 时，系统自动进入演示模式，返回预设回答，便于在没有密钥的环境中演示完整流程。

## 九、常见问答（FAQ）

问：为什么回答为空？
答：可能原因包括模型返回了空内容、请求超时、接口返回错误或网络中断。本系统会把空内容视为调用失败，向前端返回明确的中文错误提示，不会把空白结果保存为成功记录。

问：没有 API Key 可以使用吗？
答：可以。未配置 LLM_API_KEY 时系统进入演示模式，仍会执行资料检索、预设回答与问答记录保存，方便本地演示和联调。

问：如何提高检索命中率？
答：保持资料结构清晰、标题具体；在资料中使用课程中的标准术语；问题尽量包含关键概念；必要时扩充同义词说明，或改用向量检索与混合检索。

问：RAG 能完全消除幻觉吗？
答：不能。RAG 能显著降低幻觉，但模型仍可能错误概括资料。应提供引用来源、限制回答范围，并在关键场景加入人工复核。

问：如何降低调用成本？
答：控制检索片段数量与长度，减少 max_tokens，压缩提示词，对常见问题做缓存，并选择与任务难度匹配的模型。

问：温度设置为多少合适？
答：课程答疑以准确性为主，建议使用较低温度（如 0.2 到 0.4）；创意写作可以适当提高，但需接受更多不确定性。
